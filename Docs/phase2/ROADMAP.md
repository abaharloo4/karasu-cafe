# ROADMAP — Cafe Management System

## Phase 1 — Internal Cafe Management System (قطعی، سفارش‌گرفته‌شده)

### اهداف
جایگزینی مدیریت دستی اشتراک قهوه با یک سیستم داخلی قابل اتکا برای پرسنل کافه.

### Tasks
- راه‌اندازی پروژه Laravel 12 + migrations (شامل جدول‌ها و قید یکتای
  `subscription_usages`)
- Authentication پرسنل (phone/email + password، بدون OTP) + role middleware
- مدیریت مشتری (CRUD + جستجو با شماره تلفن)
- مدیریت پلن اشتراک + محصولات مجاز هر پلن (pivot table)
- تخصیص/فعال‌سازی/لغو اشتراک
- منطق مصرف روزانه (`SubscriptionService::consumeDailyItem`) با تراکنش +
  قید یکتا
- سفارش‌های حضوری عادی
- داشبورد + گزارش مصرف روزانه و اشتراک‌ها
- Seeder ها (کافه، ادمین، ۳ محصول پیش‌فرض)
- API skeleton (بدون کلاینت) برای آماده‌سازی فاز ۲

### خروجی قابل تحویل
پنل مدیریت داخلی کامل و آماده استفاده در کافه واقعی، با مستندات نصب.

### Dependencies
هیچ — این فاز مستقل و کامل است.

## Phase 2 — Online Ordering Platform for B Cafe (قطعی، سفارش‌گرفته‌شده)

**تصمیم‌های نهایی:** پیامک = ملی‌پیامک، پرداخت = زرین‌پال + کارت‌به‌کارت
(هردو قابل تنظیم از پنل ادمین)، ارسال = بله (محدوده شیراز، با نقشه نشان)،
هاست cPanel = خریداری/آماده. دیگر WordPress/WooCommerce در کار نیست. مدل
محصول: سیستم سفارش آنلاین اختصاصی «بی کافه»، شبیه تجربه اسنپ‌فود، تک‌فروشنده.

**تذکر مهم از بازبینی فاز ۱:** بررسی کد تحویلی فاز ۱ چند مشکل واقعی نشان داد
(پیاده‌سازی نیمه‌کاره فیچرهای خارج از اسکوپ، عدم اعمال RoleMiddleware، نبود
rate limiting، توکن OTP جعلی). این‌ها باید **قبل از هر کار دیگری در فاز ۲**
رفع شوند (Task 0) — رجوع کنید به Agents.md.

### اهداف
گسترش همان اپلیکیشن Laravel داخلی به یک پلتفرم سفارش آنلاین کامل (منو، سبد
خرید، دو حالت سفارش، پرداخت دوگانه، ارسال با نقشه، پنل کاربری، باشگاه
مشتریان)، بدون تغییر در منطق کسب‌وکار فاز ۱ و بدون افزودن سیستم دوم.

### Tasks
- **Task 0 (پیش‌نیاز، قبل از هر چیز دیگر):** رفع نقص‌های امنیتی فاز ۱ —
  توکن واقعی Sanctum به‌جای mock، چک مالکیت روی هر endpoint وفاداری، rate
  limiting روی OTP/login، رجیستر و اعمال سراسری `RoleMiddleware`
- ورود مشتری با OTP از طریق ملی‌پیامک — guard جدای `customer`، توکن واقعی
- منوی آنلاین عمومی (بدون نیاز به ورود) از روی جدول `products`
- سبد خرید + دو حالت سفارش: حضوری (صف مستقیم به پنل ادمین، شروع دستی توسط
  ادمین) و ارسال (اعتبارسنجی آدرس با نقشه نشان)
- یکپارچه‌سازی نقشه نشان: پنل رسم چندضلعی منطقه ارسال در ادمین + انتخاب
  آدرس مشتری (جستجو/پین) + چک point-in-polygon سمت سرور
- پرداخت دوگانه قابل تنظیم از ادمین: زرین‌پال (callback با تأیید سمت سرور) +
  کارت‌به‌کارت (آپلود رسید + تأیید دستی ادمین)
- گردش کار وضعیت سفارش (در انتظار → آماده‌سازی → آماده → تکمیل/ارسال) با
  کنترل دستی ادمین برای شروع هر سفارش
- خرید آنلاین اشتراک + استفاده رایگان روزانه آنلاین (استفاده مجدد دقیق از
  `SubscriptionService` فاز ۱، بدون پیاده‌سازی موازی)
- پنل کاربری کامل مشتری: پروفایل، آدرس‌های ذخیره‌شده، تاریخچه سفارش، وضعیت
  اشتراک، وضعیت باشگاه مشتریان
- باشگاه مشتریان: کد تخفیف تولد (شمسی، cron روزانه) + تخفیف پلکانی بر اساس
  میزان خرید — بر پایه جداول Loyalty موجود از فاز ۱، پس از رفع نقص Task 0
- سیستم ارسال کامل: delivery_zones (با boundary نقشه‌محور)، drivers،
  delivery_orders، پنل راننده با guard جدای `driver` و ورود OTP
- ردیابی سفارش مشتری
- تبدیل queue/cache/session به درایورهای سازگار با cPanel + Cron Job واحد
  برای Laravel Scheduler (شامل job روزانه تخفیف تولد)

### خروجی قابل تحویل
همان اپلیکیشن Laravel فاز ۱، گسترش‌یافته به یک پلتفرم سفارش آنلاین کامل
(منو، سفارش، پرداخت، ارسال، پنل کاربری، باشگاه مشتریان)، مستقر روی cPanel،
به‌همراه راهنمای نصب اختصاصی (شامل کلید Neshan و مشخصات زرین‌پال).

### Dependencies
Phase 1 باید کامل و در حال استفاده واقعی باشد. Task 0 (رفع نقص امنیتی) باید
پیش از هر Task دیگر این فاز انجام شود. کلید API نشان و merchant id زرین‌پال
هنوز باید از مشتری گرفته شوند.

## Phase 3 — Growth (احتمالی، دور — بدون برنامه‌ریزی فعلی)
